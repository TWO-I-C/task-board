## 核心知识：页面状态不等于数据库状态

```text
打开或刷新页面
  → 浏览器向 /api/me 发送请求，并按 Cookie 规则携带会话
  → 后端查询数据库会话，确认当前用户
  → 页面向 /api/tasks 请求任务
  → 后端只查询该用户的任务
  → 页面展示本次返回的数据
```

React 中的任务数组是页面用于显示的一份数据。账户任务的持久记录在 PostgreSQL 中。刷新会丢失这份显示状态，再向后端重新读取；刷新不会清空数据库。

| 页面状态 | 可以得出的结论 |
| --- | --- |
| 正在确认登录状态 | 尚不知道有没有有效会话 |
| 后端确认未登录（401） | 当前请求没有有效登录会话 |
| 正在加载任务 | 尚不知道该账号有多少任务 |
| 读取成功，tasks 是空数组 | 本次查询确认该账号没有任务 |
| 服务连接失败 | 本次未得到可靠结果，不能据此认定没任务或已退出 |

因此不能把所有错误都处理成“空数组”。筛选只改变当前显示哪些任务，不删除数据库记录。

代码中，`BackendSession.jsx` 管理当前身份；确认登录后才展示 `BackendTasks.jsx`，并把用户传给它。退出或身份重查会卸载旧任务区，清除列表与未保存的输入。真正的访问控制仍由后端执行，前端显示状态不能授予权限。

## 五项综合验收

### 1. 从注册走到登录

正常退出后，点击“创建账号”，使用一个未用过的练习用户名注册。

- 成功后回到登录；用户名自动填入，密码框为空，尚未出现账户任务。
- 输入错误密码，不能进入任务列表。
- 输入正确密码，自动显示该账号与任务列表。全新账号显示“还没有任务”，不需要点击“刷新任务”。

注册成功和登录成功是两件事。后端只有确认有效会话后才允许读取任务。

### 2. 在一套界面内完成任务流程

用账号 A 新增“综合验收·读书”和“综合验收·跑步”。若 A 已有其他任务，先记下原来的总数和已完成数，观察增量。

- 将“读书”勾选完成：新增两条使总数增加 2，已完成数增加 1。
- 切换“未完成”和“已完成”，两条测试任务分别出现；顶部总数不随筛选减少。
- 在已完成筛选下，把“读书”改为“综合验收·读书 30 分钟”。完成状态及总数不变。
- 尝试把名字改成全空格，不能保存；取消编辑，原名称不变。
- 对“跑步”先取消删除，确认它仍在；再确认删除，任务减少一条。

不要删除自己的其他任务。任务靠 ID 区分，名称相同也应各自独立。

### 3. 刷新与后端重启后自动恢复

- 刷新页面，不点击“刷新任务”，应自动读回 A 的任务和完成状态。
- 在运行 `npm run server` 的终端按 Control+C 停止后端，再用同一命令启动。保持 PostgreSQL 运行。
- 再刷新页面，数据仍在；会话未到期时仍能恢复当前账号。固定会话一小时到期后重新登录是正常行为。
- 展开“查看旧版浏览器任务”。原浏览器任务仍在原入口，与 A 的数据库任务分开，没有自动复制到账号中。

在开发者工具的 Network 中观察刷新：先有 `/api/me`，确认身份后有 `/api/tasks`。开发模式启用了 React Strict Mode，可能看到被取消的重复检查请求；重点看最后完成的请求和页面结果。

### 4. 两个账号与两个标签页

- 在 A 的任务输入框留下一段未提交的文字。
- 同一个 Chrome 配置中新开普通标签页，访问相同的 localhost 地址。它们共享 Cookie，并不是两个独立账号环境。
- 在第二页退出 A，第一页也应收起 A 的任务和草稿，显示登录入口。
- 在第二页登录 B，第一页应重新确认身份并自动加载 B 的任务，不出现 A 的任务或草稿。
- 重新登录 A，A 的已保存任务仍存在。切换账号清除的是页面状态，没有删除数据库记录。

Chrome 通过 BroadcastChannel 通知其他标签页身份变化；不支持它的浏览器需要刷新重新确认。普通任务增删改不会实时同步到另一个已打开的标签页，需要点击“刷新任务”；本课尚未做实时协作。

最后在普通终端运行：

```bash
npm run test:permissions
```

应看到 PASS 1 到 PASS 5。脚本在独立临时数据库中验证越权、会话失效、持久化和故障恢复，不改学习数据库。页面看不到别人的任务只是验证的一部分，直接请求接口也必须被拒绝。

### 5. 服务故障时不假装成功

以下只在本机学习环境进行，先确保没有尚未提交的数据库操作。

- 登录 A 并加载任务后，停止 Postgres.app 中的数据库服务，保留前后端运行。
- 输入“综合验收·故障恢复”并新增。应看到结果未确认或服务不可用，不能显示新增成功；输入保留，新增按钮暂停操作。
- 恢复 PostgreSQL，点击“刷新任务”。读取成功后核对任务是否已存在，再决定是否新增；页面不应自动提交草稿。这次在请求前停止数据库，预计没有创建该任务。
- 另试一次：停止数据库后刷新整个网页。应显示无法连接账户服务和“重试连接”，不应把故障当成正常退出或成功读到空列表。
- 恢复数据库，点“重试连接”，应恢复身份并自动加载任务。实验结束时保持数据库运行。

区分“刷新任务”与刷新整个网页：前者保留当前新增或编辑草稿；后者重新创建页面，未提交的草稿不保证保留。

故障发生在不同时间，结果可能不同。例如数据库已写入，但成功响应在途中丢失，页面就不能确定结果。正确操作是恢复后先读取核对，而非立即重复新增。

## 本课构建与上线边界

| 命令 | 产物 | 用途 |
| --- | --- | --- |
| `npm run dev` | 本地开发服务 | 账户界面，Vite 把 /api 转发给本机 Node 后端 |
| `npm run build -- --base=/task-board/` | dist/ | 第一阶段浏览器版，沿用 GitHub Pages 静态部署 |
| `npm run build:account` | dist-account/ | 账户界面生产构建，供后续完整系统部署使用 |

账户版构建成功，只说明前端可以打包。使用时仍要提供 Node.js API、PostgreSQL、正确的同源 /api 路由及会话配置。GitHub Pages 不能运行本项目的 Node.js 后端和 PostgreSQL，不能仅上传 dist-account 就得到完整账户服务。

两个构建目录均被 Git 忽略。本课不修改线上网站，也不上传数据库或 `.env`。

开发检查可在普通终端执行：

```bash
npm run lint
npm run build -- --base=/task-board/
npm run build:account
```

这些命令不会发布网站。浏览器验收验证实际行为，lint 和构建分别检查代码问题与打包，两者不能代替验收。
