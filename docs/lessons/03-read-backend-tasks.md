# 第二阶段 · 第 3 课：读取后端任务列表

预计 40–60 分钟，包含约 10 分钟阅读。目标：看懂后端返回的一组任务，让页面读取并显示它们，分清浏览器本地数据与后端数据。

## 当前位置

阶段 1 已完成产品功能与公开上线。阶段 2 的前两课已完成健康检查接口与页面请求，本课开始读取实际的任务结构。后续再加入写入、数据库、账号和用户隔离。

本课增加 `GET /api/tasks`，以及页面底部“本地学习实验：读取后端任务”。后端示例只供查看。上方“我的任务”的新增、编辑等操作仍使用浏览器本地保存，不会改变后端示例。

## 先预测，再运行

这次请求的数据流：

点击“读取后端任务” → `fetch('/api/tasks')` → Vite 转发 → Node.js 读取示例数组 → JSON 响应 → 前端解析并显示列表。

接口约定：使用 GET 请求 `/api/tasks`，成功返回 HTTP 200，正文如下：

```json
{
  "tasks": [
    {
      "id": "server-task-1",
      "title": "读懂任务 API 的响应",
      "completed": true
    },
    {
      "id": "server-task-2",
      "title": "在页面读取后端任务",
      "completed": false
    }
  ]
}
```

- 最外层 `{}` 是对象，`tasks` 是其中一个字段。
- `[]` 是数组，这里包含两条任务；每条任务也是一个对象。
- `id` 区分任务身份，`title` 是名称，`completed` 是布尔值：`true` 表示已完成，`false` 表示未完成。
- 字段名与类型是前后端的约定。前端会检查它们；有效的 JSON 也可能不是符合约定的任务列表。

先预测：页面应该显示几条任务，已完成几条？在上方新增个人任务，会不会改变这里的两条示例？

## 配套阅读

必读：[MDN：使用 JSON](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/Scripting/JSON)。约 10 分钟，只读“什么是 JSON？”下的“JSON 结构”“JSON 数组”“其他注意事项”，再看“对象和文本间的转换”中的 `JSON.parse()` 与 `JSON.stringify()`。不必跟做整篇英雄列表练习。

把阅读对应到本项目：后端的 `JSON.stringify()` 把数据转成响应文本；前端的 `response.json()` 读取响应正文并解析成 JavaScript 数据。JSON 是数据格式，不是数据库。

选读：[Full Stack Open：Node.js and Express](https://fullstackopen.com/en/part3/node_js_and_express/)。仅看 Express 之前用 Node.js 返回 notes 数组的例子，与我们的 tasks 数组比较；暂时不用安装 Express 或切换框架。

## 四项独立验收

1. **成功读取**：两种方式看到相同两条任务；页面显示“共 2 项 · 已完成 1 项”。
2. **识别数据来源**：在上方“我的任务”新增一条“只在浏览器保存（练习）”，再次读取后端，后端示例仍为两条。刷新页面后，上方练习任务保留；下方显示“尚未读取”，点击后恢复两条示例。验收完可删除上方练习任务。
3. **失败有明确提示**：只在终端 A 按 Control + C 停止后端，保留前端运行，再点击“读取后端任务”。应提示失败，移除上次的示例列表；不能显示“读取成功”或把失败说成“后端任务列表为空”。上方个人任务依然可用。
4. **可以恢复**：终端 A 重新执行 `npm run server`，再次点击读取，无需刷新页面即可恢复两条示例。

只停止后端而不点击读取，页面可能仍显示上次成功的列表，因为本课没有自动检查。只有重新发请求，页面才能知道这次是否成功。Vite 转发失败时可能返回 HTTP 500。

## 这两条示例存在哪里

它们写在 `server/index.js` 的 `tasks` 数组中。后端启动时把它们加载到内存；本课只有读取接口。每次重启后又从代码加载同样的示例，不能据此认为已经实现数据库保存。

前端读取后仅把响应保存在页面状态中，不写入 localStorage。刷新页面会重建状态，因此需要再次点击读取。上方个人任务则从 localStorage 恢复。
