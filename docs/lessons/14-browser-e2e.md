# 第三阶段 · 第 1 课：浏览器自动化验收

这是项目连续编号的第 14 课。预计 60–90 分钟，包含约 15 分钟阅读。

阶段 1、阶段 2 已完成学习验收。现在开始阶段 3：让已有系统可以重复检查、可靠交付。本课只学习运行浏览器测试、读懂断言、观察失败和恢复；CI、Docker 与完整系统部署分步安排。

## 本课要学会什么

以前你亲自输入任务、点击按钮、观察结果。现在由 Playwright 启动测试专用 Chromium，执行这些操作，并把实际结果与明确的预期比较。E2E 是 end-to-end，即端到端测试。

```text
测试中的操作
  → 浏览器里的真实页面
  → Node.js API
  → 临时 PostgreSQL 数据库
  → API 返回结果
  → 页面更新
  → 测试检查页面是否符合预期
```

本课不是只测一个函数，也不是让 AI 看一眼页面说“应该没问题”。你负责确定预期是什么，再检查测试是否确实验证了它。

| 检查 | 能回答的问题 |
| --- | --- |
| npm run lint | 代码里有没有规则可以发现的问题？ |
| npm run build:account | 账户版前端能不能打包？ |
| npm run test:permissions | 直接请求后端时，权限、数据隔离和故障行为是否符合预期？ |
| npm run test:e2e | 从浏览器输入和点击开始，关键用户流程是否真的跑通？ |

这些检查互相补充。E2E 全部通过也不能证明没有任何漏洞，或所有浏览器、部署环境和边界情况都正确。

## 测试环境与自己的数据

本机已经安装 Playwright 和测试专用 Chromium。本课不会使用你登录着 GitHub 的 Chrome 配置，不需要输入真实密码。

- 每次运行会建立全新的临时 PostgreSQL 集群，使用独立随机端口，并启动独立后端与 Vite 页面。
- 测试不连接本机 5432 端口的学习数据库 task_board，也不复用你在 5173 打开的页面。
- 每项测试使用新的浏览器环境；同一次执行可共享测试服务器和临时数据库，但每项测试注册不同的随机账号，避免互相依赖。
- 正常结束或测试断言失败后，会关闭测试服务、删除这次临时数据库。强制杀死进程或系统崩溃不保证正常清理；遇到异常先反馈错误，不要手动清空学习数据库。
- 本机 Postgres.app 安装目录中的 PostgreSQL 命令需要存在，学习数据库服务本身不必为测试启动；它已经在运行也无需停止。

环境准备位于 `tests/helpers/test-app.mjs`，测试生命周期位于 `tests/e2e/fixtures.js`。本课先理解其作用，不要求逐行掌握启动进程的代码。

若换一台电脑或依赖尚未安装，在项目目录运行：

```bash
npm ci
npx playwright install chromium
```

还需安装 PostgreSQL 命令。默认使用 Postgres.app 的 `/Applications/Postgres.app/Contents/Versions/latest/bin`；其他安装位置可通过 POSTGRES_BIN 指定。首次下载测试浏览器需要联网；安装好后，这五项测试访问的是本机服务。

## 先运行一次

打开新的普通终端，不是在 psql 里面；如果还在 psql，先输入 `\q`。

```bash
cd /Users/two-i-c/Documents/Codex/learning-projects/task-board
npm run test:e2e
```

默认不弹出浏览器窗口，结束后应看到 `5 passed`，然后回到终端提示符。首次启动可能稍慢，等命令结束再判断。

五项测试在 `tests/e2e/task-board.spec.js` 中：

| 测试 | 检查内容 |
| --- | --- |
| 注册、错误密码、登录与退出 | 注册不自动登录，错误密码被拒绝，刷新恢复有效身份，退出后不能恢复旧会话 |
| 同名任务：取消不删除，确认只删除一条 | 取消不发送 DELETE，确认只删除选中项，另一条的状态和持久记录保留 |
| 编辑、筛选与刷新保留 | 空名称被拒绝，筛选不改变总数，改名保留完成状态，刷新后仍正确 |
| 不同账号隔离，同一浏览器的标签页同步退出 | 独立浏览器环境互不串号，同一环境的两个标签页共享会话并响应退出 |
| 响应丢失后先核对，读取失败不伪装成空列表 | 写入已成功但响应丢失时不重复提交，恢复后查到一次新增；读取失败显示错误 |

第五项会用测试工具转发真实 POST，让临时数据库完成写入，然后拦住响应，模拟“服务器做了，页面却不知道”。它还会模拟读取请求失败。这是受控的请求故障实验，不能替代上一课真实停止数据库的实验；后者仍由权限测试覆盖。

## 看着浏览器运行一项测试

```bash
npm run test:e2e:headed -- --grep "同名任务"
```

`--grep` 按测试名称筛选，所以这次应显示 `1 passed`。会短暂出现测试专用浏览器窗口，自动操作后关闭；不要在测试期间手动点击该窗口。你的普通 Chrome 与学习数据不参与这次运行。

## 读懂一条断言

在测试文件中找到“同名任务：取消不删除，确认只删除一条”，再找到：

```js
await page.getByRole('button', { name: '确认删除', exact: true }).click()
await expect(taskBoard(page).getByText('任务已删除。', { exact: true })).toBeVisible()
await expect(matchingTasks).toHaveCount(1)
```

这里省略了中间的教学注释。这三行分别做不同的事：

- 第一行按按钮的角色和名称找到“确认删除”，再点击。
- 第二行先等待页面明确显示“任务已删除”，确认操作结束。
- 第三行重新查询匹配“同名任务”的复选框，等待数量变为 1；超时仍不符合就失败。

`matchingTasks` 是定位方式，不是一份固定不变的旧数组。测试能在页面变化后继续检查。

为什么要先等待操作结束？请求进行中，旧列表可能暂时仍有两条；此时错误的“应该有两条”也可能短暂成立。先确认完成，再检查最终结果，才能避免把过渡状态当成验收结果。

`click()` 成功只证明按钮被点击，不能证明删除正确。如果错误地把两条都删了，只做点击的脚本仍可能结束；数量断言才会发现实际为 0、预期为 1。

后续还有刷新、数量及剩余完成状态的断言，防止页面看似正确但重新读取后出错。定位优先使用用户能感知的名称和标签，不依赖按钮颜色或某个 CSS 类。

本项目勾选任务时会等待后端保存，复选框不会立即更新。因此测试使用 `click()` 后接 `await expect(...).toBeChecked()`，等待最终勾选状态。测试等待方式也必须符合产品行为，不能把“尚在保存”当成“保存失败”，更不能用固定睡眠或删除断言绕过问题。

## 五项学习验收

### 1. 完整运行并读出结果

运行 `npm run test:e2e`，确认五项通过。指出五项中哪一项检查持久化，哪一项检查用户隔离。不要只看浏览器自动关闭就认定成功。

### 2. 观察操作，并区分操作和断言

运行上面的 headed 单项命令。打开测试文件，找到一次 `click()` 和紧接着的 `expect()`，用自己的话说清：输入是什么、做了什么、期待什么结果。

### 3. 故意让错误预期失败

在 `tests/e2e/task-board.spec.js` 搜索注释“失败实验”。只把它下一行中的 `1` 临时改成 `2`，保存：

```js
await expect(matchingTasks).toHaveCount(2)
```

然后运行：

```bash
npm run test:e2e -- --grep "同名任务"
```

这次应该失败。终端应指出 expected 为 2、received 为 1，并给出断言位置。实际系统删完一条后剩一条是正确的，这次是我们故意把预期写错，目的是认识失败反馈；不能据此宣称发现了真实产品缺陷。

打开报告：

```bash
npm run test:e2e:report
```

按终端显示的本机地址查看报告，打开失败项，找到断言差异、截图或 trace。报告服务会持续占用这个终端，查看完按 Control+C 停止。

### 4. 恢复正确预期，再跑完整套件

把刚才同一处的 `2` 改回 `1`，保存，只改回这一处。然后运行：

```bash
npm run test:e2e
npm run lint
```

应再次得到 `5 passed`，lint 无错误。不要通过删掉断言、使用 test.skip、扩大超时或开启重试掩盖失败。正常开发遇到失败时，应先分清是产品错误、测试预期错误还是环境问题。

本课默认重试次数为 0。当前 HTML 报告会在下一次运行时更新，因此要先看完失败报告，再运行恢复后的测试。

### 5. 独立设计一个补充用例

先不要写代码，用三句话描述“取消编辑不会保存”的自动化验收：

1. 准备什么已保存的数据？
2. 在页面进行哪些操作？
3. 取消后以及刷新后，分别断言什么？

预期由你决定，下一轮我们再讨论是否需要补进测试。新测试应提供现有用例没有的证据，而非机械增加数量。

## 文件和报告在哪里

| 文件 | 用途 |
| --- | --- |
| playwright.config.js | Chromium、超时、单 worker、失败截图和报告配置 |
| tests/e2e/task-board.spec.js | 本课五条测试，先读这里 |
| tests/e2e/fixtures.js | 把临时应用的启动和关闭接到测试生命周期 |
| tests/helpers/test-app.mjs | 建立独立数据库与应用；不接受学习数据库地址 |
| playwright-report/index.html | 最近一次运行的 HTML 报告 |
| test-results/ | 失败时的截图、trace 等产物 |

报告及测试产物已加入 `.gitignore`。它们可能包含本次虚构账号、测试会话和请求内容，只用于本地排查；不用提交，也不用上传原始 trace。提交测试代码、配置和依赖锁文件即可。

`git status --short` 现在应该显示本课代码和文档的修改，但不应列出整批报告、截图、浏览器文件或 `.env`。

目前这些测试由你手动执行命令触发，还没有加入 GitHub Actions；提交代码不会自动跑它们。后续课程会把测试接入 CI。
